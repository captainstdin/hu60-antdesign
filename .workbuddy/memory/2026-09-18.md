## 修复：插件存储缺少 `_origin`，跨域失败

现象：`src/services/webplugStorage.js` 所有请求都没带 `_origin`，服务端不返回 `Access-Control-Allow-Origin`，浏览器直接拦截。主题同步（`theme.js`）也用这个封装，但它 `catch {}` 把异常吞了，所以一直没暴露。

改动：
- `src/services/http.js`：抽出 `parseJsonResponse` / `normalizeRequestError`，新增 `accessGet`（GET + `mode: 'cors'`，避免预检）。
- `src/services/webplugStorage.js`：新增 `ORIGIN_QUERY` 常量。读取改 GET，写入仍 POST（服务端只允许 POST 传 `value`）。

要点：`_origin` **只能传 `'*'`**。最初按「当前域名」传 `http://test.hu60.cn`，服务端把 `:` 和 `/` 全过滤掉变成 `httptest.hu60.cn`，浏览器判定为非法 `Access-Control-Allow-Origin` 直接拦截。`forum.js` 从一开始用的就是 `'*'`，全站接口都靠它工作，所以 `webplugStorage` 与之统一。请求不带 Cookie（鉴权靠 URL 里的 accessToken），`'*'` 没有额外风险。

## 修复：添加账号时选不了 AI 平台

现象：点「添加账号」打开表单，平台下拉框是空的 / 展开没有任何平台可选。

根因：`AiAccountPoolModal` → `AiAccountManager` → `AiAccountForm` 链路里，`AiAccountForm.vue` 把 `providerOptions` **这个函数本身**绑到了 `:options`：

```vue
<a-select :options="providerOptions" show-search option-filter-prop="label" />
```

`providerOptions` 导出的签名是 `export function providerOptions()`，返回分组数组。传函数引用给 `a-select` 的 `options`，antd 遍历时拿不到 `options` 字段，所以整个下拉是空的——不是数据缺失，是**少了一对括号**。

修复：模板改用 `providerSelectOptions`，script 里 `const providerSelectOptions = computed(() => providerOptions())`。

顺带确认过的 antd 行为（避免再踩）：
- 分组选项 `[{ label: '国内平台', options: [...] }, ...]` 是 vc-select 原生支持的结构，`flattenOptions` / `useFilterOptions` 都会正确下钻子项。
- `show-search` + `optionFilterProp="label"` 对分组有效：会先匹配组名，组名没中再逐个筛子项，命中子项时保留该组。

教训：这次和之前 `AI_PROVIDERS is not defined` 是同一类问题——都在「表单首次渲染」路径上，而且 Vue 的模板错误不会显示在界面上，只能看控制台或直接读代码。以后这个表单出问题先查 import 和 computed 调用。

## 修复：平台下拉点不开（层级被盖住）+ 自定义平台置顶

现象：上一轮修完「函数没调用」后，用户反馈点开平台下拉还是没有任何选项。

根因：**自己上一轮引入的层级回归**。我为了压住账号池弹窗，把账号编辑弹窗设成了 `z-index: 1200`，而 antd 的 Select 下拉弹层挂在 body 上、z-index 固定为

```
zIndexPopupBase(1000) + 50 = 1050   // select/style/index.js:265
```

下拉弹层（1050）< 编辑弹窗（1200），所以下拉被弹窗整个盖住，看着像「点了没反应」。

修复：
- 层级重新排：助手主面板 1000 → 账号池 1010 → 账号编辑弹窗 1100 → 发表确认 1200。
- `AiAccountForm.vue` 给平台下拉加 `:dropdown-style="DROPDOWN_STYLE"`（`{ zIndex: 1300 }`），让它高于宿主弹窗。验证过 `dropdownStyle` 最终作为 `attrs.style` 合并到 `PopupInner`（`vc-trigger/Popup/PopupInner.js:147`），能覆盖 `zIndex`。

同时按用户要求调整平台下拉：
- `providerOptions()` 改为**自定义平台单独置顶**（`[{label,value}]` 直接放数组首位，不进分组），其余按「国内平台 / 海外平台 / 本地部署」分组，分组内用 `id !== CUSTOM_PROVIDER_ID` 排除重复。
- `AiAccountForm.vue` 新建账号时默认选中「自定义（任意 OpenAI 兼容服务）」，`advancedKeys` 初值 `['advanced']` 让「接口地址与模型」展开，地址与模型留空等用户填。选预设平台则自动填地址+模型并收起高级项；无默认模型的平台（火山方舟）保持展开。

踩坑提醒：**antd 弹层类的 z-index 一律是 1050 这个固定基准，跟宿主弹窗不联动。** 以后凡是「弹窗里再放 Select / Tooltip / 日期选择器」，都要给那个组件的弹层单独抬 z-index，否则必然被盖。

## 新增：AI 回复支持 Markdown 排版 + 弹窗改为 80% 且隐藏不销毁

三个需求一起做：

**1. Markdown 渲染**
- 项目约定不引入 `marked` / `markdown-it`（`docs/CONTENT_PARSING.md` 明确写了），所以新增 `src/utils/markdown.js` 自写轻量渲染器，覆盖：代码块（含语言名）、h3-h6 标题、有序/无序列表、引用、表格、分隔线、段落，行内支持 `` ` ``、`**`、`*`、`~~`、`[文字](url)`。
- 安全：先用 `ESCAPE_MAP` 转义 `& < > "`，再调用 `sanitizeHtml` 二次清洗。`safeHref()` 只放行 `http(s)://`、`#`、`/`，`javascript:` 之类的链接原样回显为纯文本。已用 Node + DOMParser 桩实测过注入用例，`<script>` 和 `onerror` 都被转义。
- 只有 `resultKind === 'text'`（总结 / 分析 / 翻译 / 速览 / 标题）做排版；`reply` / `polish` 保持纯文本，因为要原样插进论坛回复框（论坛用 UBB）。结果区右上角加了「原始文本 / 排版预览」切换。

**2. 提示词调整**（`src/services/ai.js`）
- `BASE_SYSTEM` 从「不要用 Markdown」改成「可以用有限的 Markdown（### - 1. ** ` ```），排版从简，不要目录和一级标题」。
- 生成评论、润色回复这两个会把内容发到论坛的功能，在自己的 system 提示里显式覆盖为「只输出纯文本」；标题建议也单独加了纯文本要求（它是一行一个、不要编号）。

**3. 弹窗形态**
- `AiPanel` 从 `100vw × 100vh` 全屏改为 `80vw × 80vh`（`top: 10vh`，圆角 12px，`overflow: hidden`）；≤760px 的小屏仍退回全屏。
- 「隐藏不销毁」的关键改动：`AiPanel` 的 `props.open` watcher 原来在每次打开时 `result.value = ''`，这就是「每次启动重新加载」的根源，已删掉；`close()` 里的 `cancelRun()` 也去掉（关闭不该打断正在跑的请求，有显式「取消」按钮），Unmount 时仍会 abort。
- 副作用处理：结果常驻会导致「换帖子还显示上一篇总结」，所以把那个 watcher 的监听源从 `state.page` 改为 `[state.page, state.topic?.id].join('|')`，换帖子时才清空。
- `AiAssistant.vue` 的 `panelLoaded` 逻辑本来就不销毁组件，补了注释说明。

构建通过，`markdown.js` 被拆进 AiPanel 懒加载分块（79KB），主包 600KB 无增长。
